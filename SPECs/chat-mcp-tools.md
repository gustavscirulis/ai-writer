# MCP tools in Chat

Chat should load the user's configured Claude Code MCP servers using normal CLI discovery from the open workspace, including user, project/local and installed-plugin configuration. Writer continues to launch its own process with existing CLI sign-in; it does not attach to a terminal session or copy session-only flags.

Remove safe mode, the blanket MCP deny and strict empty MCP configuration. Keep manual host permissions, the existing built-in file tools and native canonical-note Edit/Write enforcement. If an Edit/Write host callback arrives after the native hook, reuse that guard and respond natively with the canonical input; never expose an override outside that guard (other notes go through [their own approval](chat-edit-other-notes.md)). Include ToolSearch and WaitForMcpServers for deferred tools and configurations without tool search. Configured CLI permissions still apply; MCP permission requests that reach the host use the existing request-local Chat approval flow with original inputs, single-use decisions and process ownership.

Native hooks and permissions must recognize names in the `mcp__server__tool` namespace while rejecting malformed names and unsupported built-in tools. Register the native hook for MCP calls as well as the available built-ins. Tool discovery may proceed without changing note-edit scope. Bound SDK initialization to sixty seconds to accommodate normal MCP/plugin startup; cancellation must interrupt that wait immediately. Chat's denial label should describe declining a tool request without implying that an MCP tool is confined to a note.

Removing safe mode also restores normal CLI customizations. MCP servers and configured custom hooks are trusted external integrations: Writer's canonical-note guard covers built-in Edit/Write, not arbitrary server or custom-hook side effects. MCP authentication remains in the terminal; interactive MCP elicitation forms are outside this change. Managed CLI policy remains authoritative: this machine restricts MCP sources to plugins, so direct user/project configurations remain blocked. Server discovery follows the open workspace path, so servers scoped to another project or passed only to a terminal session are not inherited.

Validation: native namespace/approval tests, command construction, process-level MCP allow/deny/cancellation coverage, existing note-scope tests and a real installed-CLI probe against a harmless temporary MCP server. Run frontend checks/tests and Rust tests/clippy/fmt. The internal AgentEvent envelope gains a started event with processId immediately after native registration, before SDK initialization. claude_start still returns only after verified initialization. Stop waits for either this ownership event or startup settlement before terminating, then waits for startup to settle before releasing the note. No new settings UI or dependencies.
